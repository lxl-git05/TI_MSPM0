## 3. 核心运行机制

### 3.1 定时器

- **Timer_0（1ms）**：按键扫描、LED 闪烁、（Car1）全局延时计数  
- **Timer_1（20ms）**：视觉数据更新、状态转换、`Car_Control()`、电机/MPU 更新、蓝牙  

### 3.2 小车六态（`Control.h`）

```
Car_Stop → Car_Forward（循迹 PID）
         → Car_Turn_L/R（MPU ±90°）
         → Car_Turn_F（路口直行，不看线）
         → Car_Turn_H（180° 掉头）
```

`Car_Control()` 只执行控制；**状态迁移**由各自 `Car_Control_Change_*()` 在 `Mode_Con` 中完成。

### 3.3 路口判定（`Con_Car.c`）

```c
Road_y > 210        → Track_Inter（十字路口）
isRoad_T == true    → Track_T_Inter（丁字路口，香橙派字段 11）
Over_y > 100        → Track_Over（终点）
```

### 3.4 路径记忆：状态栈

- 出发时 `Car_Status_Change(next, Store_Enable=1)` 将每次决策 **入栈**  
- 回程 `Car_Back_Enable=true` 后 **出栈 + `Car_Status_Fan_1()` 镜像翻转**（左↔右）  
- 提高题 Car1 回程也可用 `Car_To_Next_Status_From_Stack()` 简化 pop+翻转  

### 3.5 视觉 Road 数字状态机（`Orange.c` → `Road_Get()`）

按经过顺序自动采集地图数字（无需硬编码）：

```
ROAD_IDLE → 见 2 个数字 → ROAD_GET_2 (Road2)
         → 见 4 个数字 → ROAD_GET_3 (Road3)
         → 见 2 个数字且属于左/右支 → ROAD_GET_4L / ROAD_GET_4R (Road4_L/R)
```

基础/提高题转弯逻辑均依赖 `Target_Num` 与 `Road2/3/4_*` 的比较。

### 3.6 香橙派数据字段（Serial2）

| 索引 | 含义 |
|------|------|
| [2] | 循迹线偏差 x（+1000 偏移，中心=1000） |
| [4] | 路口 y（越大越近） |
| [5]–[8] | 路口数字 ID1–4（左→右，0=未识别） |
| [10] | 终点 y |
| [11] | isRoad_T（丁字路口标志） |

目标数字：`Oran_Get_Target()` 取 `[5]`（第一个非零数字）。

### 3.7 蓝牙协议（Serial3 HEX）

Car1 `BLE_SendData()` 每 20ms 广播：

| 字段 | 内容 |
|------|------|
| Data[0] | Car1 `Target_Num` |
| Data[1] | `Car2_Enable_Back`（100=true, 0=false） |
| Data[2] | Road2 编码 `L*10+R` |
| Data[3] | Road3 编码 |
| Data[4] | Road4_L 编码 |
| Data[5] | Road4_R 编码 |

Car2 `BLE_Get()` 解析到 `Car_1_Target_Num`、`Car2_Enable_Back`、Road2/3/4。

帧格式：`FF AA | len | 6×uint16 BE | 55 FE`；解析后 `Serial_New_Package[1..6]` 对应上述字段。

## 4. 各模式代码要点

### 4.1 基础题 — `Mode_Con_2`（Car1/Car2 均已标注「完成」）

**Loop 逻辑：**

1. TCRT Load + 1s 延时 → `isCarLoad`  
2. 香橙派识别 `Target_Num` + 已 Load → `Car_Start`，入栈前进  
3. 卸药（Load 变 false）或 KEY_1 长按 → `Car_Back_Enable`，弹栈翻转回程  

**Change 逻辑：**

- 去程：十字看 Road2/1/2；丁字看 Road3（栈深<8）或 Road4_L/R（最终丁字）  
- 回程：遇路口 pop+翻转，终点停车  

### 4.2 提高题 1 — `Mode_Con_3`（**已实现**）

**Car1：**

- 目标 3/4；去程同基础题  
- 到终点 Stop，卸药后栈式回程  
- 回程**首个十字路口** maneuver 完成后一次性 `Car2_Enable_Back=true`（经 HEX 广播）  

**Car2：**

- 起跑：`Target == Car_1_Target` 且已 Load；`@SkipSync=1$#` 可跳过同号校验（单车调试）  
- 去程：十字直行 → 首个丁字 Stop 等待  
- 收到 Enable 后：弹栈 → Turn_H 掉头 → 十字按 `Car_1_Target_Num` 与 Road2 转弯 → 终点 Stop  
- `Car2_Back_Enable_Tigao1` 保证 Enable 只响应一次  

### 4.3 提高题 2 — `Mode_Con_1`（未完成）

**Car1（测试）：**
- 到终点：发送文本 `@Car1_Target=%d$#`（Serial3 **文本**，非 HEX）  
- 回程：第 2 个十字路口发 `@Car2_Enable_Back$#`（文本）  
- 丁字路口仍用栈回程  

**Car2（未完成）：**

- Loop：需 `Target_Num != 0 && Car_1_Target_Num != 0` 才启动；**不要求 Load**  
- `Car_Control_Change_TiGao_2()` **整段被注释**，小车 2 提高 2 **无运动状态机**  
- 停止点/同侧异侧逻辑 **未实现**

## 6. 已知问题与技术债（Agent 应记住）

1. **`Mode_G.h` 注释与 Mode_Con 编号错位**，修改时以 `.c` 文件头为准。  
2. **提高2 Car1 用文本帧 `@...@$#`，Car2 用 HEX 帧**，协议不统一，Car2 收不到 Car1 目标号。  
3. ~~**提高1 Enable 时机**~~ → **已修正**：回程首个十字 maneuver 完成后发送。  
4. **提高2 Car2 状态机为空**，是当前最大缺口。  
5. **`Car_1_Target_Num` 在 Car2 的 `Mode_Con_1.c` 与 `Mode_Con_3.c` 各定义一次**，链接器靠 `.common` 合并，维护时易混淆。  
6. **栈深 `< 8` 判断最终丁字** 是 magic number，依赖路径长度固定。  
7. **`HandMode` / `manual_skip_sync`**：调试专用；正式比赛发 `@HandMode=0$#` `@SkipSync=0$#`。

## 7. 提高1 Serial1 手动调试（Mode_Con_3）

**分工（勿混用）：**
- **Serial2 香橙派**：循迹、路口、本车 Target 识别（正常运行始终开启）
- **Serial3 蓝牙 HEX**：Car1↔Car2 正式对车通信
- **Serial1 文本**：仅 **模拟另一辆车的蓝牙 payload**（等同 `BLE_Get` 写字段），**不**替代香橙派
- **按键 HandMode**：无香橙派/无 TCRT 时本地模拟上药、数字（与 Serial1 无关）

### 7.1 Car2 — 模拟 Car1 蓝牙（Serial1）

| 发送 | 作用（等同 Car1 `BLE_SendData` 各字段） |
|------|----------------------------------------|
| `@C1Tar=4$#` | Car1 目标号 |
| `@EnBack=1$#` | 允许 Car2 掉头 |
| `@Road2=34$#` | 中路两数字 |
| `@Road3=5678$#` | 丁字四数字 |
| `@Road4L=56$#` / `@Road4R=78$#` | 左右支路 |
| `@SkipSync=1$#` | 单车无 Car1 时跳过同号校验（仍用香橙派识号） |

本车 Target、Load：**香橙派 + TCRT**；仅 KEY_1 双击等进入 HandMode 时才不用视觉。

### 7.2 Car1 — Serial1 仅测 Enable 广播

| 发送 | 作用 |
|------|------|
| `@EnBack=1$#` | 手动置 Enable（正式由回程十字逻辑置位） |

Target、Road 仍由 **香橙派** 采集后经 Serial3 自动广播。

### 7.3 调试场景

**只测 Car2（Car1 不在场）**：香橙派正常上电 → `@SkipSync=1$#` → 上药起跑 → 丁字停 → PC 发 `@C1Tar` `@Road2` `@EnBack` 模拟 Car1 蓝牙。

**只测 Car1**：香橙派 + TCRT 正常 → 跑全程；可选 `@EnBack=1$#` 观察广播。

**双车正式**：不用 Serial1；`@SkipSync=0$#`。

## 8. 提高题2 修改建议（尚未实施）

### 8.1 优先：统一 Car1→Car2 通信

**问题：** 函数体全注释，Car2 不会动。

**建议分两阶段状态机：**

**阶段 A — 去停止点（`Car_Back_Enable == false`）：**

- 参考已注释草稿：十字直行 → 丁字停车。  
- **同侧/异侧分支**（需结合地图确认，建议逻辑）：  
  - 比较 `Target_Num` 与 `Car_1_Target_Num` 在 Road3 中的位置（左 duo `[0],[1]` vs 右 duo `[2],[3]`）。  
  - **同侧**：可能在第一个丁字停，或通过某条短支路停在中线等待区（按赛题场地实测定）。  
  - **异侧**：可能需多过一个十字或走不同支路再停；可用「Car2 目标在 Road3 左且 Car1 在右 → 先直行/再某弯」规则表驱动，**不要**与 Car1 共用同一套 Road4 终弯逻辑。  
- 停止点判定：`Track_T_Inter` + 可选 `StatusStack` 记录，便于阶段 B 复用。

**阶段 B — 收到 Enable 后去 Car1 病房（`Car_Back_Enable == true`）：**

- 可参考提高1 Car2 回程：十字按 **Car1 目标** 与 Road2 转弯。  
- 终点 `Track_Over` 停车；RGB 可亮红（Loop 注释已提到）。  
- 此阶段 **不入栈或单独栈**，避免与阶段 A 混淆；或阶段切换时 `StatusStack_Clear` 再记录新路径。

### 8.2 提高题 2 — 实现 Car2 `Car_Control_Change_TiGao_2()`

**问题：** 使用 `Inter_cnt >= 2` 在十字路口发文本 Enable；赛题要求 **4 数字丁字路口转向完成后**。

**建议：**

- 改为：回程遇到 `Track_T_Inter` 且 `StatusStack_Size >= 8`（或 ROAD 状态机已到 4L/4R）并完成 **`Car_Turn_L/R` 后** 置 `Car2_Enable_Back`。  
- 与提高1 区分：提高2 是 **丁字**，提高1 是 **十字**。  
- 统一用 HEX `Data[1]=100`，去掉 `@Car2_Enable_Back$#` 文本。

### 8.3 提高题 2 — Car1 回程 Enable 时机

**问题：** 使用 `Inter_cnt >= 2` 在十字路口发 Enable；赛题要求丁字路口转向完成后。

**建议：** 回程 `Track_T_Inter` + 栈深足够 + 转向完成后置 `Car2_Enable_Back`；统一 HEX。

### 8.4 提高题 2 — Car1 到达后通知 Car2

**建议：** 依赖 HEX `Data[0]` 持续广播；或扩展第 7 字段作到达沿。

### 8.5 工程维护建议

- 将 `Car_1_Target_Num` 单一定义到 `BLE.c` 或 `Comm.h`  
- 正式赛前：`@HandMode=0$#` `@SkipSync=0$#`  
- 联调顺序：HEX 双向 → 提高1 → 提高2
